# Fabric в SCREEN

Расширение 1.19.0 включает mineflayer-fabric 0.2.1. Поддержка подключается
автоматически сразу после создания бота, включая login, configuration и PLAY.
Ограничение старой установленной версии только на Minecraft 26.1.x снято:
используется обмен Fabric API для 1.14–26.x в пределах версий Mineflayer.

Обычный сервер не получает Fabric-каналов или brand библиотеки. На Fabric
бот адаптирует модовые предметы, блоки, сущности и меню. Неизвестные состояния
блоков считаются твёрдыми; точная геометрия и игровая логика Java-модов требуют
отдельных данных и обработчиков.

Журнал показывает обнаружение Fabric, число реестров и записей, добавленные
данные и предупреждения с кодами. Модовые меню открываются как общие окна
после получения содержимого. Сетевые ошибки и FABRIC_TIMEOUT допускают
переподключение; постоянная несовместимость останавливает повторные попытки.

Данные восстанавливаются при переходе через прокси, ошибке и отключении.
Отложенная адаптация и незавершённое меню старого соединения отбрасываются.
Коллизии заглушек сохраняются при повторной загрузке `prismarine-block`
плагинами. Навигация обновляет классификацию блоков, ID строительных предметов
и кэш после адаптации в PLAY или перехода на другой сервер той же версии.

`pnpm build:pathfinder` собирает библиотеку из `vendor/mineflayer-fabric`,
а её исходники, тесты и лицензии сохраняет в `pathfinder-source.json`.
Установщик, обновление worker и ZIP содержат готовую библиотеку без внешнего
локального пути и установки новых npm-зависимостей.

Проверка: `node --no-deprecation --test fabric.test.mjs worker.test.mjs`.
TCP-стенд воспроизводит Fabric разных поколений и обычные серверы.
Это эмуляция протокола, а не полный Java-сервер с модами пользователя.
